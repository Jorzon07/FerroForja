Rol: Analista de Sistemas e Ingeniero de Requisitos (ISO 29148 / ISO 25010)

¿Qué permitió crear este prompt?

  • Consolidación estricta de las 12 Reglas de Negocio Oficiales (RN-01 a RN-12): bloqueo de stock negativo (RN-01), desactivación lógica de productos con historial (RN-02), compras completas (RN-03), Costo Promedio Ponderado (RN-04), cliente obligatorio en ventas (RN-05), pago en efectivo (RN-06), reincorporación de devoluciones (RN-07) y ajustes de stock exclusivos para Administrador (RN-08).
  • Matriz preliminar de permisos clasificando privilegios entre ADMINISTRADOR y USUARIO_OPERATIVO.
  • Catálogo de 12 Casos de Uso con flujos principales, alternativas y manejo de errores.

2 Diseño Técnico y Arquitectónico del Sistema Etapa 2 — Diseño
Rol: Arquitecto de Software y Diseñador de Sistemas

¿Qué permitió crear este prompt?

  • Arquitectura tradicional por capas: Controller → Service → Repository → MySQL en paquetes desacoplados.
  • Separación obligatoria en dos repositorios independientes: backend/ y frontend/ (sin monorepo).
  • Modelo Entidad-Relación y diagrama Mermaid con 16 tablas relacionales.
  • Diccionario de datos completo para MySQL 8.0: tipos DECIMAL(15,2) para COP, DECIMAL(12,3) para inventario y DECIMAL(15,4) para CPP (prohibición de FLOAT y DOUBLE).
  • Catálogo completo de endpoints REST y DTOs, adoptando el estándar RFC 9457 (ProblemDetail) para respuestas de error.
  • 6 Diagramas de secuencia de flujos críticos: Login, Venta con bloqueo pesimista, Compra con CPP, Devoluciones, Ajuste manual y Cancelación.
  • Diseño de seguridad: sesiones web en servidor (HttpSession), cookies JSESSIONID con HttpOnly/SameSite, protección CSRF y contraseñas con BCrypt.

4 Implementación Completa, Integración y Entrega Funcional Etapa 4 — Desarrollo
Rol: Equipo Completo de Desarrollo Senior (Backend Java, Frontend React, DBA)

¿Qué permitió crear este prompt?

  • Núcleo de Inventario Atómico: Implementación de restarExistenciaConCerrojo con SELECT ... FOR UPDATE en AlmacenNivelRepository, bloqueando compras/ventas simultáneas para prevenir saldos negativos (RN-01).

  • Ajustes de Inventario: Exclusivos para Administrador con motivo documentado y auditoría inmutable (RN-08, RN-11).
  • Frontend Completo en React: 12 pantallas funcionales (Login, Dashboard, POS Mostrador, Historial de Ventas, Recepción de Compras, Historial de Compras, Inventario/Kárdex, Catálogo, Terceros, Devoluciones, Auditoría y Usuarios).
